# Sync is peer to peer, merges per field and never purges

Sync keeps a person's own devices in step directly, with no server, account or cloud copy: devices find each other on the same Wi-Fi (mDNS) and over Tailscale (remembered addresses and an optional typed one per paired device), talk TCP with TLS 1.3 and pin each other's keys after pairing with an 8-digit code. Any device relays what it holds, so a group converges through any path. Changes are recorded in the change log (ADR 0008) with the origin device, a hybrid logical clock and a sequence, and merge field by field: different fields both survive, text is the replay of every stored record in clock order, merged three-way (by line, then by word) wherever a record was written against a different text than the replay holds, and only the same words changed on two devices raise a Conflict for the user. Every other clash takes the newest value and is logged as Resolved automatically. Nothing is ever purged, so a deleted row is its own tombstone and no old device can bring it back. Sync is a Module, off by default, and inert when off: no socket, mDNS, timer or task exists.

The decision is hard to reverse because the change log, the clock columns and "deleted rows stay forever" become the format every device must share, and it is easy to wonder why we did not use a hosted store.

## Considered Options

- **A server or cloud store**: rejected; the point is that the diary and tasks never leave the user's devices, and it means accounts and running something.
- **Whole-record last-writer-wins**: rejected; a Priority set on the phone and a Due date set on the Mac would cancel each other.
- **CRDT text for every field**: rejected; it needs a different storage format for all text and still cannot say "you rewrote the same sentence twice". Replaying the change log with each record's previous text (`prev`) is enough, and the rare real clash is shown to the user.
- **Conflicts for every field**: rejected; asking about a Priority is a chore. Only text people wrote is worth a question.
- **Keep purging deleted rows after 30 days**: rejected; a device away for longer would resurrect them, and tombstones would need their own expiry rules.
- **Relay or cloud rendezvous for devices on different networks**: rejected for v1; Tailscale covers it without us hosting anything.

## Amendment: what was built around the protocol

- **Group membership is synced data, signed.** Pairing with one member joins the whole group. Members that did not take part learn of the newcomer through a `sync_introduction` (signed by the introducing member; a signed `direct` flag marks the device it actually paired with, and only a direct introduction can undo a Forget). Forget is a signed `sync_revocation`; every member drops and refuses the key and a device that is paired again lifts it with a newer `lifted` decision. Members are equals: any paired member can introduce or lift. There is no remote wipe, and a forgotten device is not told, it shows Not nearby.
- **Later edits survive a Conflict.** Edit merged is rebuilt from the live text (merged against the other version), not from the text stored when the Conflict was raised, so edits made since stay. A delete met by an edit from another device that had not seen it, and a group clash, are logged as Resolved automatically whichever clock is later; the data outcome is unchanged (both land).
- **The typed Address is synced.** One typed Address per paired device lives on the synced `sync_device` entity as a value field (newest edit wins, logged as Resolved automatically on a clash; clearing it is an edit). Every member shows it, can edit it and dials it; a device ignores the Address typed for itself. This device's name is unique in the group like a paired device's (ignoring case and accents). Conflict times follow the Time format Preference.
- **Leave tells the group.** Leave first sends a signed revocation of this device to the members it can reach (the same mechanism as Forget), then forgets locally; they drop it and log "‹name› left the group". With nobody reachable it leaves at once, locally, and a device never told keeps retrying.
- **Remote text waits for the editor.** A record for a record or field being edited is stored, counted and relayed at once, but its values are held (`editing_sessions` leases of 120 s, renewed every 30 s by the editor) and merged when the editor releases. With Sync off nothing is held or written.
- **One logger per shared Activity event.** A session, pairing, pause or failure that both devices live through is logged by the device with the lower id; own events (rename, forget, leave) by the device itself; named events have deterministic ids so every device makes the same row.
- **Safety nets.** Every direct pairing backs up both databases first (own rotation of five). A peer more than 5 minutes ahead, or records stamped that far ahead, pause syncing rather than win every merge; so does a data-version mismatch. TCP keepalive notices a vanished peer in about 15 seconds.
- **Android runs the network only in the foreground** (plus a best-effort 5 s flush on leaving: no wake lock and no `WAKE_LOCK` permission, so it completes when the app is switched away with the screen on but not reliably once the screen is off; the next foreground catches up), only on a suitable link (mobile data needs the setting), and only with Sync on (`sync_power`). Closing the last desktop window ends the app, and with it Sync.
- **The system's local network permission (macOS 15+, Android 17+) is expected and designed around** (Apple TN3179, Android local network permission). macOS keeps an app off the LAN until the person allows it: outgoing connections to LAN addresses and all mDNS sends and receives fail with `EHOSTUNREACH` ("No route to host"); accepting incoming connections does not need it and a VPN interface such as Tailscale is outside it. No API reports the state, so the rules are:
  - **Ask at a good moment.** `src-tauri/Info.plist` holds `NSLocalNetworkUsageDescription` (Tauri merges it into the bundle and embeds it in the dev binary). The Welcome page says on a Mac that Mnemora will ask; the session manager probes right after the network starts (a UDP datagram to the mDNS group, which also raises the prompt) and repeats it, every 3 s for 30 s, then every 30 s while it fails and every 60 s while it works.
  - **Detect, never guess from one failure.** `LocalNetwork` (`local_network.rs`) counts `EHOSTUNREACH` from dials to LAN addresses (private and link-local; not loopback, not Tailscale) and from the probe. "Blocked" needs at least 3 failures spread over at least 30 s with no LAN success between (the first operations can fail before the prompt is answered), and any LAN dial or probe that works clears it. A working probe discounts dial failures (a switched-off phone also answers `EHOSTUNREACH`). Android reports the OS's answer with `sync_local_network_os`, which blocks at once.
  - **Never silent.** Blocked shows as a banner with "Open Settings" on Devices and in the Pair sheet (the Local Network pane, falling back to Privacy & Security; on Android the app's settings), "Blocked by Local Network setting" on rows that are not otherwise connected (`PeerState::BlockedByLocalNetwork`), the amber "!" badge and a Home card like a pause, and one Activity line (`Kind::Blocked`, not again within ten minutes) when it starts.
  - **Depend on it as little as possible.** A paired device is dialled at its remembered and typed addresses whether or not mDNS finds anything, so a denied Mac still syncs through the other device's dial; Tailscale addresses are started first in the dial race; the Mac's Pair sheet shows "Or on your phone: Pair by address… ‹address›" so a first pairing works without mDNS. Apple's dns_sd on macOS was considered and left out: it needs the same permission and would add a macOS-only path.
  - **Android** declares `ACCESS_LOCAL_NETWORK` now (the app targets SDK 36, where nothing is enforced). It is requested only when Sync is turned on and from the denied banner, never while Sync is off, and only on Android 17+ (`LocalNetworkPolicy`); after "Don't ask again" the banner opens the app's settings.
- **Schema.** Core migrations 3 to 6 (clock columns, `fields`, `editing_sessions`, `prev`), Todo 5 (Comment `edited`), and the Sync Module's own migrations hold the local and synced `sync_` tables.
