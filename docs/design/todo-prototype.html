Todo: prototypes for every decision

Two parts. Part 1 is a working mock of the Todo Module on desktop and phone, built from Mnemora's real tokens. Try it: add Tasks with natural language (Pay rent tomorrow 9am every month #Home), tick them, undo, open a Task, change its date, time, Repeat and List, write notes with checklists, drag to reorder, use the keyboard (↑ ↓ Space Enter Esc ⌫ T). Part 2 is the catalogue: every small decision, from the overall concept down to storage columns, each with options, a small preview, a recommendation and a notes box. Nothing is assumed: anything not in "Already settled" is a question for you. Picks are saved in this browser; Copy my picks at the bottom gives you text to paste into the chat. Items tagged live in mock change the mock as you pick; items tagged low-level are engineering decisions.

0 Already settled

IDDecision
G1The Module is Todo; one thing in it is a Task. A - [ ] line inside Markdown is a Checklist item, never a Task. (Glossary updated.)
G2A Task has one Due date with an optional time. There is no separate "when"/"deadline" pair. An undated Task never appears in date-based views.
G3Overdue = open and its Due date (and time, if set) has passed. Overdue Tasks are never moved silently.
G4Repeat is in v1 and basic: every N days, weeks (on chosen weekdays), months, years; counted either from the Due date (fixed schedule) or from the day it was done. Doing a repeating Task records the occurrence and moves the same Task to its next Due date.
AppInherited from the app and ADRs: Rust owns data and rules (0001); compile-time Module contract, no Module imports another (0002); SQLite, UUIDv7 ids, created_at/updated_at, soft delete (0003); writes go to the core change log (0008); Todo hue is teal (--hue-todo); Components only from src/lib/ui; time format, date format and week start come from core Preferences; toasts bottom-right, max 3, 4s; Undo instead of confirm (N10); timestamps relative under 7 days.
