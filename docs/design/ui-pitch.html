S · Vibrance strategy

How we reconcile calm, pro and warm (your day-to-day feel) with unique and vibrant (your first brief). This is the biggest visual decision, because it decides where colour is allowed.

Evidence and references
  • Arc "Spaces": each context tints the whole sidebar and background (that's S5). Users like knowing where they are; the cost is that the app never looks neutral.
  • Things 3 / Bear: almost no colour on surfaces; colour marks meaning (tags, today). That's the S1 or S3 end of the spectrum.
  • Linear: dark neutral surfaces with subtle gradient glows on hero moments, and themes generated in LCH. That's S1 with D1.
  • Amie / Daylio: colour-rich, playful and celebratory. That's S4.
  • Technical cost: every strategy is just token rules (no per-Component work), because Components read --accent, --cur, --surface and so on. S2 (presets) multiplies design and QA effort per preset, not code.
  • Accessibility: gradients behind text (S1, S4 hero) need text contrast of at least 4.5:1, which white on the mid-chroma accents in C1/C3 meets. S4's translucent cards need a solid fallback if backdrop-filter is slow on low-end Android WebView.

D · Direction (surfaces, shape, depth)

The base material of the app: background warmth, how cards separate, corner radius and depth. Each one maps to a reference family you picked.

Evidence and how directions are built
  • Colours are defined in OKLCH (perceptually even lightness), which Tailwind v4 uses natively in @theme. Light, dark and OLED ramps stay balanced across hues.
  • Dark mode uses lighter surfaces instead of shadows for elevation, plus a 1px inner highlight. Shadows are nearly invisible on dark backgrounds.
  • OLED true black: the background and sidebar are #000, and surfaces are only lifted to about 14% lightness, so OLED pixels can switch off. Pure white text on pure black can "smear" on some OLED panels, so the ink colour stays slightly off-white.
  • A direction is one token file (src/lib/theme/directions/*.css). If you choose S2 (presets), several of these ship and the user switches between them.

C · Accent palettes (brand + one colour per Module)

Each Module owns a hue: its nav icon, its selection colour and, under S5, its whole tint. Home and Settings already have one. Journal, Todo and AI are reserved for later.

Evidence
  • Per-context colour identity: Arc Spaces, Capacities object types, Linear team colours. It helps orientation when switching quickly.
  • All accents are chosen at OKLCH lightness 55–72% so white text on them reaches about 4.5:1. The pastel palette, C5, uses dark text instead (--on-accent flips).
  • The user can still override the brand accent in Settings under any strategy. S3 makes that override the main feature.

F · Font pairings (UI + display + mono)

All are OFL-licensed and can be bundled locally as variable WOFF2 with a Latin subset (about 30–90 KB each) through Fontsource. Satoshi and General Sans were excluded because their licence restricts redistribution.

Evidence
  • From the research: everything below is on Fontsource 5.3.x as @fontsource-variable/*, except Instrument Serif and Commit Mono (static weights only).
  • The UI font carries 95% of the text, so readability at 13–15px matters most. Geist, Inter, Manrope, Plus Jakarta, Instrument Sans and Figtree all have tall x-heights and clear numerals.
  • The display font appears only in the greeting, page titles and the clock. That's where personality lives cheaply.
  • The clock uses font-variant-numeric: tabular-nums so digits don't jitter every second.
  • F3's mono is Commit Mono in the real app. This preview substitutes JetBrains Mono because Commit Mono isn't on Google Fonts.

A · App icon

Each icon is shown at 112px, 32px and 16px, and in a light and a dark dock. It must stay readable as a 16px tab icon and on an Android launcher (where it gets masked to a circle). The final version is exported to every size with cargo tauri icon.

Already decided in the session (for reference)

Navigation

The desktop sidebar is resizable and collapses to an icon rail (Claude-app style) with a toggle and ⌘\. It never hides. On the phone: a bottom bar with 4 Modules you choose plus More, and no centre "+" for now.

Window and themes

A custom integrated titlebar (traffic lights inside the sidebar). Themes: Light, Dark, System and True black (OLED). Density: Comfortable and Compact (the phone always uses touch sizes).

Stack

Svelte 5 + Vite 8, Tailwind v4 with our own OKLCH tokens, Bits UI (plus Ark UI for the bottom sheet and splitter), svelte-sonner, paneforge, TanStack Virtual. Motion uses Svelte built-ins and View Transitions. Capture is ⌘N in the app only.
